<h3 align="left">Zero‑knowledge proof is a cryptographic function that underpins secure transactions in the blockchain network and other everyday services. This code implements a zero‑knowledge proof function using the Qiskit library (a quantum “assembler”) for a quantum processor. It is divided into three parts: generating a private key, generating a public key, and verifying that the key belongs to the account.

# Algorithm architecture
# The algorithm is logically divided into three parts: generating a private key, where we create a hidden sequence of bits, which will be used in the main part to verify that the public key belongs to the account; generating a public key, which serves as a marker for verifying the result; and the main part, which takes the private key as input and produces the public key as output. In the subsequent description of the algorithm, it will be assumed that the length of the private and public keys is 256 bits.

# Generation of the private key
# Quantum states are initialized to |0⟩, after which each of the 256 qubits is transformed using the Hadamard operator into the state (∣0⟩+∣1⟩)/√2. Measuring each such state yields 0 or 1 with a 50% probability; the measured values are then written to a classical register and become the account’s private key.

# Public key generation
# Before describing the process of generating a public key, it is worth mentioning the reasons why values from the private sequence are directly substituted into the scheme.When creating entangled Bell states, you can obtain states in two bases: |ϕ⟩ = (∣00⟩ + ∣11⟩)/√2 and |ψ⟩ = (∣01⟩ + ∣10⟩)/√2.2. Let’s consider the possible measurement options for the |ϕ⟩ basis: if a one is obtained in the first qubit, then it becomes known that the second one will also be a one; if, however, a zero is obtained when measuring one of the qubits, then the second one will also be a zero. In the case of the |ψ⟩ basis, the situation is reversed: if a one is measured first, then the second qubit will be a zero with 100 % probability, and vice versa. Here, it is worth noting that if the basis and one of the measurements of two qubits are known, the value of the second qubit in the pair can be reconstructed. Accordingly, when creating the algorithm structure, it is necessary to take into account that both of these components cannot be public data. Therefore, the sequence of bases is the private key. At the previous stage, a sequence of 256 bits was generated; we assign the value 0 to the basis |ϕ⟩ and the value 1 to the basis |ψ⟩. This is necessary in order to store the bases as a key in the computer’s classical memory. Now let’s consider the generation of the public key directly. Here, you will already need 512 qubits. The first 256 qubits are initialized to the state |0⟩; the second half is initialized to |0⟩ or |1⟩ according to the corresponding value in the private key, after which a pairwise entanglement process is carried out between the 1st and 257th, 2nd and 258th, etc., qubits. Entanglement is achieved by sequentially applying the Hadamard operator to the first qubit, which transforms it into the state (∣0⟩+∣1⟩)/√2, and then applying the two‑qubit CNOT operation, after which the basis states |ϕ⟩ and |ψ⟩ are obtained. Note that when generating Bell states, it is the second qubit in the pair that determines the resulting state basis (if it is 0, the basis is |ϕ⟩; if it is 1, the basis is |ψ⟩), which is why these values were chosen for recording them in the classical register. After generating Bell states in this way, we measure only the second row (the second qubits in the pair, from the 257th to the 512th) and record the results in the classical register — this sequence becomes the account’s public key.

# Checking whether the public key belongs to the account. 
# The first step is to perform a bitwise XOR operation between the public and private keys; the resulting sequence will then be compared with the first row of the quantum circuit, but everything in order. Let’s call the sequence xor_key.. The next step is to create a quantum circuit using the same principle as in the previous stage; thus, we have 256 entangled qubit pairs in bases corresponding to the values of the private key. 
# We measure only the first row and compare it bit by bit with the xor_key sequence; if the values match, the second qubit in the pair remains unchanged; if they turn out to be different, the logical X (NOT) operation is applied to the second qubit, which flips the qubit’s amplitude. After that, the second row is measured. Thus, the output should be the same sequence as in the public key.
